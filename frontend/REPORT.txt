1. ОБЩЕЕ ОПИСАНИЕ
────────────────────────────────────────────────────────────────────────────────

Был создан полноценный фронтенд для двустороннего маркетплейса услуг
ServicePort с нуля. Проект построен на базе существующей заготовки Vite
(содержавшей только стартовую страницу) и полностью переработан под
требования технического задания.

Стек технологий:
  • React 19.2.5          — UI-библиотека
  • Vite 8.0.10           — сборщик и dev-сервер
  • Tailwind CSS v4       — утилитарный CSS (плагин @tailwindcss/vite)
  • TanStack Query v5     — управление серверным состоянием (useQuery, useMutation)
  • Zustand v5            — глобальное состояние (авторизация)
  • React Router v6       — клиентская маршрутизация
  • Axios 1.14.0          — HTTP-клиент с JWT-интерцептором

2.2. API-слой (src/api/)
──────────────────────────

  src/api/client.js
    Axios-инстанс с baseURL: '/api'. Содержит интерцептор запросов,
    который читает токен из useAuthStore.getState().token и добавляет
    заголовок Authorization: Bearer {token} к каждому запросу.

  src/api/auth.js
    Функции: login(data), register(data).
    POST /api/auth/login, POST /api/auth/register.

  src/api/categories.js
    Функции: getAllCategories(), getCategoryById(id).
    GET /api/categories, GET /api/categories/{id}.

  src/api/services.js
    Функции: getAllServices(), getServiceById(id),
    getServicesBySpecialist(specialistId), getServicesByCategory(categoryId),
    createService(data), updateService(id, data), deleteService(id).

  src/api/specialists.js
    Функции: getSpecialistById(id), getSpecialistByUserId(userId),
    createSpecialist(data), updateSpecialist(id, data).


2.3. Zustand Store (src/store/)
────────────────────────────────

  src/store/useAuthStore.js
    Хранит в памяти (без localStorage — намеренно, по требованиям ТЗ):
      • token         — JWT-токен
      • user          — { email, role }
      • specialistProfileId — ID профиля специалиста
    Методы: setAuth(token, user, specialistProfileId),
            setSpecialistProfileId(id), clearAuth().


2.4. Компоненты (src/components/)
────────────────────────────────────

  src/components/Navbar.jsx
    Залипающая навигационная панель (sticky, backdrop-blur). Слева —
    логотип с индиго-квадратом и названием ServicePort. Справа:
      — если не авторизован: кнопка «Войти»
      — если CLIENT: email + кнопка «Выйти»
      — если SPECIALIST: ссылка «Дашборд» + email + кнопка «Выйти»
    При выходе вызывается clearAuth() и редирект на /auth.

  src/components/ProtectedRoute.jsx
    HOC-компонент. Если нет token → редирект на /auth. Если передана
    prop role и user.role не совпадает → редирект на /.

  src/components/ServiceCard.jsx
    Карточка услуги: название, описание (3 строки, overflow hidden),
    бейдж категории, цена в MDL, длительность в минутах, кнопка
    «Подробнее» → /specialists/{specialistProfileId}.
    Анимация при наведении: translateY(-2px) + подсветка рамки.

  src/components/CategoryFilter.jsx
    Горизонтальные фильтр-пилюли. Кнопка «Все» + кнопка на каждую
    категорию. Активная пилюля подсвечивается индиго-цветом.


2.5. Страницы (src/pages/)
────────────────────────────

  src/pages/AuthPage.jsx
    Двухколонный layout:
      — Левая панель (видна от 768px): брендинг, логотип, заголовок с
        градиентным текстом, три фичи, декоративные radial-gradient блобы.
      — Правая панель: переключатель вкладок «Войти» / «Регистрация»
        с анимацией. Форма входа: email + пароль. Форма регистрации:
        firstName, lastName, email, пароль + выбор роли (CLIENT /
        SPECIALIST) через карточки-кнопки.
    Использует useMutation (TanStack Query). При успехе: setAuth() в
    Zustand + редирект (/ для CLIENT, /dashboard для SPECIALIST).
    Отображает ошибки из API-ответа.

  src/pages/CatalogPage.jsx
    Публичная страница. Загружает категории и услуги через useQuery.
    Фильтрация: при выборе категории queryKey меняется и автоматически
    делается запрос к /api/services/category/{id}.
    Во время загрузки — анимированные скелетоны (shimmer-эффект).
    Если услуг нет — пустое состояние с иконкой и текстом.

  src/pages/SpecialistPage.jsx
    Читает :id из URL. Загружает профиль специалиста и его услуги
    параллельно через два useQuery. Отображает:
      — Аватар с инициалами (градиентный круг)
      — Email, бейдж «Проверен» (если verified=true)
      — Рейтинг звёздами (1–5, заполненные / пустые)
      — Опыт с правильным склонением (год/года/лет)
      — Биография
      — Сетка услуг через ServiceCard

  src/pages/DashboardPage.jsx
    Защищена ProtectedRoute (role=SPECIALIST). Состоит из двух секций:

    Секция «Мой профиль»:
      — Отображает bio, experience, rating, verified
      — Кнопка «Редактировать» открывает встроенную форму ProfileForm
      — Если профиль не создан — предлагает создать через ту же форму
      — PUT /api/specialists/{id} или POST /api/specialists

    Секция «Мои услуги»:
      — Список услуг с inline-редактированием (форма ServiceForm
        разворачивается прямо под элементом)
      — Кнопка «+ Добавить услугу» → форма создания сверху списка
      — Кнопка «Изменить» → форма редактирования
      — Кнопка «Удалить» → модальное окно подтверждения ConfirmModal
      — После любой мутации инвалидируется queryKey 'specialist-services'
